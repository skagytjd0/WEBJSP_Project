## 2. 요구사항명세 - 기능

### 1.1 기능 요구 사항 - 사용자 (USER)

| 요구사항 ID | 요구사항분류 | 요구사항명 | 요구사항 상세 설명 |
| :--- | :--- | :--- | :--- |
| **USER-001** | 사용자 | 회원가입(비회원) | 아이디, 비밀번호, 이름,모바일, 이메일, 주소을 입력받아 회원가입 (아이디는 중복 불가)<br>회원번호 자동 생성 |
| **USER-002** | 사용자 | 로그인(회원,관리자) | 아이디와 비밀번호를 DB와 대조하여 사용자 인증<br>관리자는 정해진 아이디와 비밀번호 사용<br>각 권한별 맞는 메뉴출력 |
| **USER-003** | 사용자 | 로그아웃(회원,관리자) | 로그인 정보를 초기화하고 메인 페이지 |
| **USER-004** | 사용자 | 회원 정보 조회(회원,관리자) | 아이디, 비밀번호, 이름,모바일, 이메일, 주소확인 |
| **USER-005** | 사용자 | 회원 정보 수정(회원,관리자) | 아이디, 비밀번호, 이름,모바일, 이메일, 주소 변경 |
| **USER-006** | 사용자 | 회원 탈퇴(회원) | 회원 탈퇴 |
| **USER-007** | 사용자 | 회원 목록 (관리자) | 회원 정보 출력가능 |
| **USER-008** | 사용자 | 악성 회원 추방(관리자) | 규정무시회원 추방 |
| **USER-009** | 사용자 | 회원 상태 및 정보 관리 (관리자) | 회원정보을 수정합니다 |

### 1.2 기능 요구 사항 - 경매 (ORDER)

| 요구사항 ID | 요구사항분류 | 요구사항명 | 요구사항 상세 설명 |
| :--- | :--- | :--- | :--- |
| **ORDER-001** | 경매 | 경매 입찰 | 관리자가 새로운 경매 물품(상품명, 시작 가격)을 등록합니다. |
| **ORDER-002** | 경매 | 경매 목록 (회원, 관리자) | 현재 경매중인 물건을 봅니다 |
| **ORDER-003** | 경매 | 경매 취소(관리자) | 경매 진행 도중 상품에 하자가 발견되거나 부정한 거래 정황이 있을 경우,<br>관리자가 해당 경매 자체를 중단하고 무효화(데이터 삭제 혹은 상태 변경) 처리한다. |
| **ORDER-004** | 경매 | 경매품 등록 (회원,관리자) | 새로운 경매 대상 물품을 시스템에 등록하는 기능이다.DB 상품 테이블에 저장. |

### 1.3 기능 요구 사항 - 고객문의 (INQUIRY)

| 요구사항 ID | 요구사항분류 | 요구사항명 | 요구사항 상세 설명 |
| :--- | :--- | :--- | :--- |
| **Inquiry-001** | 고객문의 | 문의 등록(회원) | 로그인한 회원은문의사항을 등록할 수 있어야 함 |
| **Inquiry-002** | 고객문의 | 문의 목록(관리자,회원) | 로그인 사용자가 회원일 경우, 본인이 작성한 문의 내역만 출력함,로그인 사용자가 관리자일 경우, 모든 회원이 작성한 전체 문의 내역을 출력함 |
| **Inquiry-003** | 고객문의 | 문의 수정(회원) | 회원은 자신이 등록한 문의 내용 중 '답변대기' 상태인 항목에 한해 제목과 내용을 수정할 수 있음 |
| **Inquiry-004** | 고객문의 | 답변 (관리자) | 관리자는 회원이 접수한 문의 상세 페이지에서 답변 내용을 입력하여 등록할 수 있음 |
| **Inquiry-005** | 고객문의 | 답변수정 (관리자) | 관리자는 이미 작성하여 등록한 답변의 내용을 선택하여 수정할 수 있음 |

### 1.4 기능 요구 사항 - 낙찰내역 (WIN)

| 요구사항 ID | 요구사항분류 | 요구사항명 | 요구사항 상세 설명 |
| :--- | :--- | :--- | :--- |
| **WIN-001** | 낙찰내역 | 낙찰자 선정 (관리자) | 경매 마감 시 관리자가 마감 처리를 요청하면, BidDAO를 통해 해당 상품의 최고가 입찰자를 조회하여 선정하고,DB 낙찰 테이블에 저장 |
| **WIN-002** | 낙찰내역 | 낙찰 목록 조회 (회원) | 회원이 경매 결과 최종 승리자로 선정되어 낙찰에 성공한 상품들을 모아서 조회하는 메뉴이다.<br>상품 정보와 함께 최종 결제해야 할 금액을 보여준다. |
| **WIN-003** | 낙찰내역 | 전체 낙찰 내역 관리 (관리자) | 관리자 전용 메뉴로, 지금까지 마감된 모든 경매의 낙찰 데이터<br>(낙찰자 ID, 최종 낙찰 금액, 결제 유무 상태)를 종합적으로 조회하고 제어한다. |
| **WIN-004** | 낙찰내역 | 낙찰 취소 처리 (관리자) | 낙찰자가 기한 내에 대금을 결제하지 않거나(미입금), 정당한 사유로 취소를 요청할 경우<br>관리자가 해당 낙찰 건을 취소 처리하고 경매 상태를 되돌린다 |

### 1.5 기능 요구 사항 - 입찰내역 (BID)

| 요구사항 ID | 요구사항분류 | 요구사항명 | 요구사항 상세 설명 |
| :--- | :--- | :--- | :--- |
| **BID-001** | 입찰내역 | 입찰 내역 조회 (회원) | 일반 회원이 메인 메뉴의 마이페이지를 통해 과거 자신이<br>어떤 상품에 얼마로 입찰에 참여했었는지 개인 입찰 이력 리스트를 필터링하여 조회한다. |
| **BID-002** | 입찰내역 | 상품별 입찰 현황 (관리자) | 관리자가 특정 경매 상품을 선택하면, 해당 상품에 접수된 모든 입찰 기록을 DB에서 입찰 금액 내림차순조회 |
| **BID-003** | 입찰내역 | 입찰 취소 (관리자) | 특정 회원의 오입 입력 요구나 담합 등의 부정 입찰 이력이 적발되었을 때,<br>관리자가 해당 입찰 데이터 한 건을 BidDAO에서 강제로 삭제(무효화)하는 기능이다. |

## 3. 요구사항명세 - 비기능

### 2.1 비기능 요구사항 - 데이터(DATA)

| 요구사항 ID | 요구사항분류 | 요구사항명 | 요구사항 상세 설명 |
| :--- | :--- | :--- | :--- |
| **DATA-001** | 데이터 | 경매품 정보 관리 | 등록된 모든 경매 물품 데이터는 관계형 데이터베이스에 저장한다. |
| **DATA-002** | 데이터 | 회원 정보 관리 | 회원 계정 정보는 DB의 회원 테이블(MEMBER 테이블)에 회원 ID를 기본키(PK)로 설정하여 관리한다. |
| **DATA-003** | 데이터 | 문의사항 정보관리 | 1:1 문의 및 답변 데이터는 DB의 고객문의 테이블에 저장한다 |
| **DATA-004** | 데이터 | 낙찰내역 정보관리 | 최종 낙찰 데이터는 DB의 낙찰 테이블에 저장한다. |
| **DATA-005** | 데이터 | 입찰내역 정보관리 | 실시간 입찰 데이터는 DB의 입찰 테이블에 입찰 고유번호를 기준으로 누적 저장(INSERT)한다. |
